## 1. Decisions summary

| Topic | Decision |
| --- | --- |
| App name | **PersonalDolar** |
| Visual identity | White and blue palette (see §8.1) |
| Password reset | **Not included** (no email sending) |
| Stack | React (Vite + TypeScript) frontend + FastAPI backend |
| Database | SQLite in development, Postgres in production (same SQLAlchemy models, Alembic migrations) |
| Auth | Email + password, Argon2 hashing, JWT stored in an **httpOnly cookie** |
| Simulator | Runs in the **backend** as a pure Python module, exposed via API, unit-tested |

| API contract | OpenAPI generated by FastAPI; TypeScript client generated from it |

- `openapi-typescript` (generates API types from the backend's OpenAPI). Added in milestone 2: its current release does not yet support TypeScript 6
- Tooling: oxlint, Prettier, Vitest + React Testing Library

## 4. Data model

All tables have `id` (integer PK), `created_at` and `updated_at`. Every user-owned table has `user_id` (FK → `users.id`, `ON DELETE CASCADE`, indexed).

### `users`

| Column | Type | Notes |
| --- | --- | --- |
| email | varchar(255) | unique, stored lowercase |
| password_hash | varchar(255) | Argon2 |

### `categories`

| Column | Type | Notes |
| --- | --- | --- |
| user_id | FK | |
| name | varchar(100) | |
| kind | enum(`income`, `expense`) | |
| parent_id | FK → categories, nullable | `NULL` = top-level category; set = subcategory |

- Unique on (`user_id`, `kind`, `parent_id`, `name`).
- Only two levels: a subcategory's parent must be top-level and of the same `kind` (validated in the service layer).
- Default set from plan.md §4.2 is created when the user registers. Income categories have no subcategories by default.

### `transactions`

| Column | Type | Notes |
| --- | --- | --- |
| user_id | FK | |
| type | enum(`income`, `expense`) | determines the sign |
| date | date | indexed together with `user_id` |
| amount | numeric(12,2) | `> 0`; for salary this is the **net** amount |
| gross_amount | numeric(12,2), nullable | only for income; `gross_amount ≥ amount` |
| category_id | FK → categories | top-level, `kind` must equal `type` |
| subcategory_id | FK → categories, nullable | must be a child of `category_id` |
| note | varchar(500), nullable | |

- **Salary (§4.4):** a salary is an income transaction with `gross_amount` set. Effective deduction rate = `(gross − net) / gross`, computed and returned by the API (not stored). Totals and simulations always use `amount` (net).

### `investments`

| Column | Type | Notes |
| --- | --- | --- |
| user_id | FK | |
| name | varchar(100) | |
| type | enum(`stock`, `fund`, `etf`, `crypto`, `deposit`, `real_estate`, `other`) | |
| platform | varchar(100) | free text |
| amount_invested | numeric(14,2) | `≥ 0` |
| current_value | numeric(14,2) | `≥ 0`, updated manually |
| value_updated_at | date | date of the last manual update |

Gain/loss (`current_value − amount_invested`) and gain % (`gain / amount_invested`, `null` if the amount invested is 0) are computed, not stored.

## 5. Authentication and authorization

- **Register:** `POST /api/auth/register` validates the email and a password of at least 8 characters, hashes it with Argon2, creates the user, seeds the default categories (in the same DB transaction) and logs the user in.
- **Login:** verifies the hash and issues a JWT (`sub` = user id, `exp` = 7 days) signed with HS256 using `JWT_SECRET`.
- **Cookie:** `access_token`, `HttpOnly`, `SameSite=Lax`, `Secure` in production, `Path=/api`. The token is never readable from JavaScript, so it is not exposed to XSS.
- **Logout:** clears the cookie.
- **Same origin:** in development Vite proxies `/api` to FastAPI. In production the backend serves the built frontend, or both sit behind the same domain. This avoids CORS and third-party cookie issues.
- **CSRF:** `SameSite=Lax` plus requiring `Content-Type: application/json` on every mutating endpoint.
- **Authorization:** a `current_user` dependency guards every router except auth. Every query filters by `user_id`. Fetching another user's resource returns **404** (not 403, so the API does not reveal that the resource exists). Foreign keys sent in a body (e.g. `category_id`) are checked to belong to the current user.
- Login errors return a generic message ("Invalid email or password").

## 6. API

Prefix `/api`. JSON in and out. Money fields are serialized as **strings** (`"1234.50"`) so precision survives JSON. Errors use FastAPI's standard shape (`{"detail": ...}`), with 422 for validation errors.

### Auth

| Method | Path | Description |
| --- | --- | --- |
| POST | `/auth/register` | create account + set cookie |
| POST | `/auth/login` | set cookie |
| POST | `/auth/logout` | clear cookie |
| GET | `/auth/me` | current user (`401` if not logged in) |

### Categories

| Method | Path | Description |
| --- | --- | --- |
| GET | `/categories?kind=` | tree: categories with nested subcategories |
| POST | `/categories` | `{name, kind, parent_id?}` |
| PATCH | `/categories/{id}` | rename |
| DELETE | `/categories/{id}` | **409** if it (or one of its subcategories) has transactions |

### Transactions

| Method | Path | Description |
| --- | --- | --- |
| GET | `/transactions?from=&to=&type=&category_id=&subcategory_id=&page=&page_size=` | ordered by date desc; returns `{items, total}` |
| POST | `/transactions` | create |
| GET / PATCH / DELETE | `/transactions/{id}` | read / update / delete |

### Investments

| Method | Path | Description |
| --- | --- | --- |
| GET | `/investments` | list with computed gain/loss, plus a portfolio totals block |
| POST | `/investments` | create |
| GET / PATCH / DELETE | `/investments/{id}` | `PATCH` with `current_value` also updates `value_updated_at` (defaults to today) |

### Dashboard

| Method | Path | Description |
| --- | --- | --- |
| GET | `/dashboard?from=&to=` | see below |

Response:
- `income_total`, `expense_total`, `savings` (= income − expense), `savings_rate` (= savings / income, `null` if income is 0)
- `expenses_by_category`: `[{category_id, name, total, subcategories: [{id, name, total}]}]`. Expenses without a subcategory are grouped under `"(none)"`. The frontend uses this for the pie chart drill-down without a second request.
- `investments`: `{total_invested, current_value, gain, gain_pct, by_type: [{type, current_value}]}`

The frontend computes the period (current month by default, current year, or custom range) and sends `from` and `to`.

### Simulator

| Method | Path | Description |
| --- | --- | --- |
| GET | `/simulator/defaults` | pre-filled inputs: `starting_amount` (current portfolio value), `avg_monthly_expenses` (see §7.5), `inflation_rate` 0.02, return scenarios 0.03 / 0.05 / 0.07 |
| POST | `/simulator/accumulation` | Mode A |
| POST | `/simulator/goal` | Mode B |
| POST | `/simulator/withdrawal` | Mode C |

The simulator endpoints take all inputs in the request body and are stateless. They read no user data, which keeps them pure and easy to test. They still require authentication.

## 7. Simulator

Lives in `backend/app/simulator/` as pure functions that take and return dataclasses / Pydantic models. All arithmetic uses `Decimal`; results are rounded to 2 decimals only at the output.

### 7.1 Common inputs

- `starting_amount ≥ 0`
- `contribution ≥ 0`, `frequency ∈ {weekly: 52, monthly: 12, yearly: 1}` periods per year (`n`)
- `scenarios`: `{pessimistic, base, optimistic}` annual return rates (e.g. `0.03`, `0.05`, `0.07`)
- `inflation_rate` (annual, e.g. `0.02`)
- `current_age`, `avg_monthly_expenses`

### 7.2 Conventions

- Periodic rate from an annual rate: `r_p = (1 + r)^(1/n) − 1` (compound-equivalent, so 12 months at `r_p` equals exactly `r` over a year).
- Contributions are made at the **end** of each period.
- Real value (today's dollars) at time `t` years: `nominal / (1 + inflation)^t`.
- Each scenario is computed independently with the same inputs.

### 7.3 Mode A — Accumulation

Input: `horizon_years` (1–60).
Iterate period by period: `balance = balance × (1 + r_p) + contribution`.
Output per scenario, for each year `0..horizon`: `{year, age, nominal, real, total_contributed}`. Also returned: `years_of_expenses_covered = real_final / (avg_monthly_expenses × 12)`.

### 7.4 Mode B — Goal

Input: `target_amount` (in today's dollars), `years`, and a flag `target_is_real` (default `true`, so the target is inflated to the nominal value at the target date).
With `N = years × n` periods and `FV` = the nominal target:
- `r_p ≠ 0`: `PMT = (FV − PV·(1+r_p)^N) · r_p / ((1+r_p)^N − 1)`
- `r_p = 0`: `PMT = (FV − PV) / N`
- If `PMT ≤ 0`, the starting amount already reaches the goal: return `0` and `already_reached = true`.

Output per scenario: `required_contribution` (per period of the chosen frequency) and `total_contributed`.

### 7.5 Mode C — Withdrawal / retirement

Input: `retirement_age > current_age`, `withdrawal_mode ∈ {percent, fixed}`, `withdrawal_rate` (e.g. `0.03`) or `monthly_withdrawal` (in today's dollars), `end_age` (default 100).
1. **Accumulation phase** until `retirement_age`, as in Mode A.
2. **Withdrawal phase**, monthly until the money runs out or `end_age` is reached. The balance keeps growing at the scenario's monthly rate, and the withdrawal grows with inflation every year:
   - `percent`: first-year annual withdrawal = `withdrawal_rate × balance at retirement`, divided by 12, then indexed to inflation.
   - `fixed`: `monthly_withdrawal` in today's dollars, converted to nominal at retirement, then indexed to inflation.

Output per scenario:
- `balance_at_retirement` (nominal and real)
- `monthly_income` (in today's dollars)
- `expenses_coverage_pct = monthly_income_real / avg_monthly_expenses`
- `lasts_until_end = true/false`, plus `depletion_age` when it does not last
- yearly series `{age, nominal, real}` for the chart

**`avg_monthly_expenses` default:** the user's total expenses over the last 12 full months ÷ the number of months that have data (at most 12). Returns `0` if there is no data; the frontend then asks the user to enter a value.

### 7.6 Validation

Rates must be between −0.5 and 0.5 and horizons between 1 and 60 years. Withdrawal mode requires `retirement_age < end_age ≤ 120`. Out-of-range input returns **422**.

## 8. Frontend

| Route | Page |
| --- | --- |
| `/login`, `/register` | public |
| `/` | Dashboard: period selector, 4 KPI cards, expense pie with click-to-drill-down, investments block with a pie by type, button to the simulator |
| `/transactions` | table with filters (period, type, category), create/edit dialog; the gross field appears for income |
| `/categories` | income and expense trees; add, rename, delete (shows the 409 message) |
| `/investments` | table with gain/loss in $ and %, portfolio totals, quick "update value" action |
| `/simulator` | tabs A / B / C; form pre-filled from `/simulator/defaults`; line chart with 3 lines (nominal/real toggle); results table; **visible disclaimer** ("Projections are estimates, not financial advice") |

- Authenticated routes are wrapped in a guard that calls `/auth/me`. A `401` from any request redirects to `/login`.
- Currency is formatted with `Intl.NumberFormat('en-US', {style: 'currency', currency: 'USD'})`. Money stays a string until it is displayed.
- Responsive layout (mobile first) with a sidebar on desktop.

### 8.1 Visual identity

- Name shown in the header and the browser tab: **PersonalDolar**.
- White and blue palette, defined once as Tailwind / shadcn theme tokens (CSS variables) so no component hard-codes colors:
  - background `#FFFFFF`, surfaces `#F5F8FF`, borders `#DCE5F5`
  - primary blue `#1D4ED8` (buttons, links, active nav), hover `#1E40AF`, light accent `#DBEAFE`
  - text `#0F172A`, muted text `#64748B`
- Charts use shades of blue for categories, plus green / red only to mark gains and losses.
- The three simulator scenarios: pessimistic `#93C5FD`, base `#2563EB`, optimistic `#1E3A8A`.

## 9. Testing strategy

| Layer | Tool | What |
| --- | --- | --- |
| Simulator | pytest | known values calculated by hand / in a spreadsheet: zero rate, zero contribution, a goal already reached, depletion at an exact age, weekly vs monthly vs yearly frequency |
| Services | pytest | dashboard aggregations, salary deduction rate, average expenses, default category seeding |
| API | pytest + httpx `TestClient`, temporary SQLite | happy paths, 422 validation, 401 without a cookie, **404 when accessing another user's data**, 409 when deleting a category in use |
| Frontend | Vitest + RTL | formatting helpers, form validation, drill-down component |

Target: 100% coverage of `simulator/` and ≥ 80% of the backend. CI (GitHub Actions, `.github/workflows/ci.yml`) runs `ruff`, `mypy`, `pytest`, `oxlint`, `prettier`, `tsc`, `vitest` and the production build on every push and PR.

## 10. Configuration and local development

Backend environment variables: `DATABASE_URL` (default `sqlite:///./dev.db`), `JWT_SECRET`, `COOKIE_SECURE` (default `false` locally), `ACCESS_TOKEN_DAYS` (default 7).

```text
backend:   uv sync && uv run alembic upgrade head && uv run fastapi dev app/main.py   # :8000
frontend:  npm install && npm run dev                                                # :5173, proxy /api → :8000
types:     npm run gen:api   # openapi-typescript http://localhost:8000/api/openapi.json (from milestone 2)
```

## 11. Deployment (after the MVP works locally)

A single service: a multi-stage Dockerfile builds the frontend, and FastAPI serves `frontend/dist` as static files plus `/api`. Managed Postgres. Candidates on free tiers: Render or Fly.io (Postgres from Neon or the provider itself). Migrations run on deploy (`alembic upgrade head`).
