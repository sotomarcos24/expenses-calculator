### Secrets

**No findings.** Checked:

- The deploy hook is read only from `secrets.RENDER_DEPLOY_HOOK` into an env var (`ci.yml:138`), never written to a file or echoed; `curl` output goes to `/dev/null` and error messages name the secret, not its value (`ci.yml:141`). GitHub masks the value in logs.
- `RENDER_PUBLIC_URL` is a non-secret variable (`vars.*`), correctly not a secret.
- `backend/.env.example` adds only a commented, empty `RENDER_GIT_COMMIT=`.
- `docker-compose.yml:9,37` holds throwaway example credentials and a `dev-only` `JWT_SECRET`, explicitly labelled as such (`ENVIRONMENT: development`, so the production guard would reject the value if reused). Their exposure through the published port is covered by F2 (Permissions).
- `.gitignore` ignores `.env`; `check_no_secrets.py` (CI job `no-secrets`, also a `deploy` prerequisite) blocks any tracked `.env.*` other than `.env.example`, `*.db` and key files.
- No secret value or URL of the deployed service appears in the README text.
